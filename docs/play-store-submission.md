## 1. 데이터 보안 (Data safety) 설문 답안

### 1.1 앱이 수집·전송하는 데이터 — **예**

| Play 카테고리 | 데이터 유형 | 수집 | 공유 | 필수 여부 | 목적 |
|---|---|---|---|---|---|
| 개인 정보 | 이름 (닉네임) | O | X | 선택 | 앱 기능, 계정 관리 |
| 개인 정보 | 이메일 주소 | O | X | 필수 | 계정 관리 |
| 개인 정보 | 사용자 ID | O | X | 필수 | 앱 기능, 계정 관리 |
| 메시지 | 기타 인앱 메시지 (편지 제목·본문) | O | X | 필수 | 앱 기능 |
| 앱 활동 | 앱 상호작용 (편지 열람 기록) | O | X | 필수 | 앱 기능 |

**공유(Sharing)는 전부 "아니요".** Supabase·Vercel은 회사를 대신해 처리하는 서비스 제공업체이므로 Play 기준의 '공유'에 해당하지 않는다.

### 1.2 수집하지 **않는** 것 (설문에서 체크 해제)
- 위치, 주소록, 사진·동영상, 파일, 캘린더, 통화 기록, 마이크
- 결제 정보 (인앱 결제 없음)
- 광고 ID, 기기 ID (광고 SDK 없음)
- 크래시 로그·진단 정보 (Crashlytics 등 미탑재)
- 분석 데이터 (Analytics SDK 미탑재)

> 확인 근거: `libs.versions.toml`·모듈 `build.gradle.kts`에 Firebase/Analytics/Crashlytics/Ads 의존성 없음. 매니페스트 권한은 `INTERNET`, `ACCESS_NETWORK_STATE` 둘뿐.

> **푸시 알림:** `PushTokenRepository` 코드는 있으나 FCM 의존성과 `google-services.json`이 없어 **런타임에 토큰을 수집하지 않는다.** 나중에 푸시를 붙이면 데이터 보안에 "기기 ID 또는 기타 ID"를 추가해야 한다.

### 1.3 보안 관행
- **전송 중 암호화:** 예 (모든 통신 HTTPS)
- **데이터 삭제 요청 가능:** 예 — 앱 내 계정 삭제(`delete_my_account`) + 이메일 요청
- **독립 보안 검토를 거쳤는지:** 아니요
- 삭제 요청 URL: `https://efreedom-alpha.vercel.app/privacy`

### 1.4 개인정보처리방침 URL
```
https://efreedom-alpha.vercel.app/privacy
```

## 5. 업로드 절차

1. **앱 만들기** — Play Console → 모든 앱 → 앱 만들기
   - 앱 이름: 위 3항
   - 기본 언어: 한국어
   - 앱/게임: 앱 · 무료
2. **비공개 테스트 트랙** 생성 → AAB 업로드
   - 파일: `app/build/outputs/bundle/release/app-release.aab`
   - 첫 업로드 시 **Play 앱 서명** 사용에 동의 (권장)
3. **대시보드의 필수 작업** 순서대로 처리
   - 앱 액세스 권한 (로그인 필요 → 심사용 테스트 계정 제공)
   - 광고: 없음 / 콘텐츠 등급 설문 / 타겟층 / 데이터 보안(1항) / 정부·금융 앱 아님
4. **스토어 등록정보** — 문구(3항) + 그래픽(4항)
5. **프로덕션 출시** 신청 → 심사 (보통 며칠)

> **심사용 계정이 필요하다.** 앱이 소셜 로그인만 지원하므로 심사자가 들어갈 수 없다. '앱 액세스 권한' 항목에 테스트용 계정(이메일/비밀번호)이나 로그인 우회 방법을 반드시 적어야 하며, 없으면 반려된다.
