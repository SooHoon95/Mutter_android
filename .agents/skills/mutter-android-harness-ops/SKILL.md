# Mutter Android 하네스 운용

지침·자동메모리·작업 문서를 쓰고 고칠 때의 규칙. 기능 코드 규칙은 `mutter-android-architecture`·`mutter-android-conventions` 등을 따른다. iOS 저장소(`~/Desktop/Code/Mutter`)의 `mutter-harness-ops`와 같은 운용이다 — 한쪽 하네스 구조를 바꾸면 다른 쪽도 맞출지 확인한다.

배경: Opus 5 세대는 스스로 판단·검증·완결한다. 촘촘한 금지 나열·일괄 검증·적극 위임 지시는 토큰만 늘린다. 그래서 규칙을 **판단 기준**으로 쓴다.

## 규칙은 판단형으로 쓴다

- 새 규칙은 "언제 적용하고 언제 적용하지 않는지"를 같이 적는다. 예외가 있으면 규칙 안에 쓴다.
- 규칙에는 **왜**(어떤 실제 사고에서 나왔는지)를 한 줄 남긴다.
- 기존 규칙은 실제 충돌·오작동이 확인됐을 때만 손댄다.
- **예외 — 도메인 하드 제약은 조건 없이 쓴다**: RPC 시그니처는 `letter-app/supabase/migrations` 기준, RPC 파라미터 DTO `= null` 금지, 비밀값(`secrets.properties`·`*.jks`·`google-services.json`·Play 키) 커밋 금지, JDK 17, 런타임 동작 검증("컴파일 통과" ≠ "검증"), 커밋 단위 분리, 프로덕션 트랙 업로드는 사용자 확인 후.

## 작업 문서 — `tasks/`

| 파일 | 용도 |
|---|---|
| `tasks/todo.md` | 현재 작업 계획 + 리뷰. 끝난 작업은 `tasks/archive/`로 옮긴다 |
| `tasks/lessons.md` | 최근·고유 교훈(세션 시작 시 검토) |
| `tasks/lessons-archive.md` | 1개월 이상 지났거나 스킬·자동메모리로 흡수된 교훈(필요해질 때 만든다) |
| `tasks/archive/` | 완료된 계획·리포트(`git mv`로 이력 보존) |

**todo.md** — `## 현재 작업 — <제목> (YYYY-MM-DD)` 아래 `- [ ]` 항목, 끝나면 `### 리뷰`에 변경 요약·검증 증거.

**lessons.md** — 최신을 위로.

```
### YYYY-MM-DD — 한 줄 제목
- 상황: 무엇을 하다 무엇이 잘못됐나
- 교정: 사용자가 어떻게 바로잡았나
- 규칙: 같은 실수를 막을 검증 가능한 행동 규칙
```

오래 쓸 기술 교훈은 해당 스킬로 옮기고 lessons에서는 아카이브한다(스킬이 단일 진실 소스).

## 사고 강도(effort)

- 기본 **low~medium**. 올리는 경우: 원인 불명 버그, 여러 모듈·저장소(Android·iOS·웹)에 걸친 설계, 되돌리기 어려운 변경, 서버 계약·인증 판단. 올렸으면 이유를 한 줄로.

## 리뷰 보고

- 찾은 것은 **전량 보고**, 사용자 요약은 **심각도 필터**(기본 HIGH 이상). 확신이 없으면 빼지 말고 **확신도**(확실 / 추정 / 미확인)를 적는다.
- 각 지적에 근거(스킬·규칙·`파일:라인`)와 심각도(CRITICAL / HIGH / MEDIUM / LOW / INFO).
- 리뷰를 서브에이전트에 맡길 때 이 규율을 프롬프트에 그대로 쓴다.

## 문서 분량

- 상한 **계획·스펙 15KB, 리포트·요약·리뷰 6KB**. 넘기면 근거를 문서에 적는다.
- 채우기 섹션 금지(빈 "리스크"·"향후 과제", 빈 표, 헤더만 남은 블록).

## 검증·위임 강도

루트 `AGENTS.md` §2·§4가 단일 진실 소스다. `.Codex/AGENTS.md`(OMC 관리)의 일괄 강제 문구는 재동기화로 원복되므로 손대지 않고 루트 `AGENTS.md`의 우선 선언으로 이긴다.

## 하네스 변경 후 확인

- `AGENTS.md`·커맨드가 참조하는 스킬 이름이 `.Codex/skills/*/SKILL.md`의 `name:`과 일치한다(dangling 0).
- 각 SKILL.md에 `name`·`description`이 있고 `name`이 디렉터리명과 같다.
- 실제 세션(`Codex -p`)에서 스킬이 목록에 노출되고 대표 프롬프트에 맞는 스킬이 호출되는지 확인한다.
